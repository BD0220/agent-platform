# abundance · 本地运行说明

> 网页版单机应用：双击启动，浏览器打开 `http://127.0.0.1:8000`，没有登录页。

## 启动

**双击项目目录里的 `start.bat`**（首次运行自动建 venv + 装依赖 + 复制 `.env`），浏览器会自动打开。

或者命令行：

```bat
.venv\Scripts\python.exe run.py                 :: 自动开浏览器
.venv\Scripts\python.exe run.py --no-browser    :: 只起服务
```

停止：在窗口里按 `Ctrl+C`，或直接关窗口。

### 环境要求

- **Python 3.11 / 3.12**。3.13+ 没验证过（部分依赖还没出对应 wheel）；
  本机默认 `python` 不是 3.12 时，用环境变量指定解释器：

  ```bat
  set ABUNDANCE_PYTHON=C:\Users\you\AppData\Roaming\uv\python\cpython-3.12.14-windows-x86_64-none\python.exe
  start.bat
  ```

- 项目路径**尽量不带空格**（`D:\new agent\...` 这种带空格的历史上建 venv 出过问题）。
  必须放带空格目录时，把 venv 建到外面再用 `ABUNDANCE_PYTHON` 指回来。
- venv 是**每个项目各自一份**，装在项目根的 `.venv`，不要和别的项目共用；
  装依赖走 `pip install -e ".[dev,langgraph]"` —— **少了 langgraph 不报错**，
  只是工作流引擎静默退回线性模式，排查起来非常费劲。

## 前置配置（`.env`，项目根目录）

| 变量 | 必填 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 是（用 DeepSeek 时） | 填你的 key；用别家模型就填对应环境变量 |
| `MYSQL_*` | 建议 | `MYSQL_HOST/PORT/USER/PASSWORD/DATABASE`；不配则兜底 SQLite |
| `AGENT_GATE_MODE` | 否 | `plan`（默认）：开场确认一次计划，之后自动放行；`all`：每次交接都确认 |
| `ABUNDANCE_PORT` | 否 | 默认 8000，被占用时改一个 |

- MySQL 库和专用账号如果还没建：`scripts\migrate_sqlite_to_mysql.py` 会在连接时自动建表；
  旧 SQLite 数据迁移：`.venv\Scripts\python.exe scripts\migrate_sqlite_to_mysql.py`（幂等，可重跑）。
- DeepSeek 模型名只认 `deepseek-flash` 和 `deepseek-v4-pro`。

## 界面怎么用

1. **左上「＋ 新建会话」** → 在下面输入框发需求（如"写一个判断回文的 Python 函数并运行"）。
2. 群聊里会看到谁在干活、内容实时长出来；**开场会弹一次黄色「执行计划确认」**：
   「✓ 确认继续 / ↺ 打回重做（可填修改意见） / ■ 终止任务」。
   确认之后**不会再逐次打断**，进度仍然可见 —— 每次工具调用会画成一张卡片
   （工具名 / 操作对象 / 耗时 / 结果大小，点开能看结果预览）。
3. 左侧**历史会话**随时点开回放；`⋯ 知识库 / 统计` 里有任务统计和 token 用量。
4. 交付物（需求分析.md / 代码.py / 测试报告.md）落在工作空间目录，聊天里点「查看」直接看内容。

## 常见问题

| 问题 | 处理 |
|---|---|
| 8000 端口被占 | 设环境变量 `ABUNDANCE_PORT=8010` 再启动 |
| 开着 VPN 时页面转圈 | 程序已自动把 127.0.0.1 加入 NO_PROXY，一般不会撞；仍不行就关代理试 |
| 报 400 invalid model | `.env` / `.data/settings.json` 里的模型名改成 `deepseek-flash` |
| 报缺 API Key | `.env` 里填 `DEEPSEEK_API_KEY`，或界面「模型 · 密钥」里填；缺 key 会明确报错，不会静默降级 |
| 想重置数据 | 删 `.data/platform.db`（SQLite 模式）或清空 MySQL 里的 tasks/memories 表 |
| 确认条一直弹 | 老版本 bug（`handoff_done` 没广播）。已修；仍出现就确认进程是重启过的新版本 |

## 改了代码之后

- 后端（`backend/`）改完必须**重启进程**才生效（没有热重载）。
- 前端（`frontend/`）改完刷新页面即可；`index.html` 里 js/css 的 `?v=` 是缓存版本号，
  改了样式或脚本记得一起改，否则浏览器可能还在用旧文件。
