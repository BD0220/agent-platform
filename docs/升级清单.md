# abundance 专业化升级任务清单

> 参照对象：DevFlow-AI（`D:\new agent\dev flow\DevFlow-AI`，已读源码审计）。
> 原则：只移植"编排层与质量机制"，不追功能广度；每条都能对应一次真实踩坑或一个面试高频题。
> 状态：**已全部完成（2026-10-18）**，T1–T7 全部落地并分三次提交，测试 64/64 通过。
> 实施记录见 `docs/改动记录.md` 第十一章。

## P0 必做（治已踩过的坑，约 3 天）

### T1 结构化输出契约（0.5 天）
- **做什么**：新建 `agents/contract.py`，定义 `AgentResult{role, status: ok|partial|failed, artifacts{requirements/code/report}, evidence[{type,ref}], confidence, notes}`；三个子 Agent 的提示词追加契约说明，输出改为信封式 JSON；`sub_agents.py` 解析并校验必填字段，解析失败记 `failed` 并自动重试一次；交付物落盘只接受 `status=ok` 且 artifacts 非空。
- **治什么**：空壳输出 `[程序员已生成代码]` 覆盖 19KB 真代码（2026-10-13 实测）——根因是平台无法区分"做完了"和"说了句漂亮话"。
- **DevFlow 出处**：全仓 pydantic 类型化（WorkflowSpec/Task/TaskResult/Observation）。
- **验收**：喂故意退化的输出 → 平台打回而非落盘；现有端到端用例不回归。

### T2 独立审查员 + 置信度阈值（1 天）
- **做什么**：`definitions.py` 新增"审查员"角色（提示词只喂交付物+证据，**不给对话历史**，输出 `{verdict, findings[], evidence_refs[]}`）；`graph.py` 在 agent 与 conclusion 之间插 `observe` 节点；`verdict=reject` 走现有打回通道重做；`confidence < 0.6` 或 `evidence` 为空 → 自动重做，不进人工闸门。
- **治什么**：主 Agent 自审自评——生成者与审查者共享上下文，"知道想写什么就觉得写对了"；计算器任务 19 轮里主 Agent 被迫亲自干测试员的活。
- **DevFlow 出处**：ObserverAgent + findings 分类学（evidence_gap / low_confidence / missing_safety_review）+ 0.45 阈值触发 replan。
- **验收**：构造"报告说未通过但运行证据全过"用例 → 判通过；构造真失败用例 → 抓出并给出证据引用。

### T3 上下文预算管理（1 天）
- **做什么**：新建 `agents/context.py` 组装器：每次调 LLM 前按预算分级拼装（system / 记忆 / 证据 / 近期轮次 / 工具结果），超预算先压缩早期轮次（留摘要），**工具结果（证据）不压缩**；`call_agent.py` 接入；`max_turns` 从轮数硬截断改为"轮数 + token 预算"双闸。
- **治什么**：`max_turns=30` 硬截断 = 长任务失忆；有修复环节的任务常在复测前被轮数掐死（2026-10-13 复盘的结构性问题）。
- **DevFlow 出处**：token 预算分配 + 压力分级 + progressive compaction。
- **验收**：20+ 轮长任务早期需求不丢失；每次调用 token 用量可观测。

### T4 证据链与引用（0.5 天）
- **做什么**：RAG 注入的记忆带来源前缀（`[记忆#id · 任务类型 · 日期]`）；conclusion 总结改为"结论 + 证据指针"（测试报告行号 / 退出码 / 记忆 id）；前端总结气泡展示证据，可点开查看。
- **治什么**：测试结论被报告文字骗过（判"未通过"实为全过）——结论没有贴着证据走。
- **DevFlow 出处**：citations 逐任务携带、聚合进 WorkflowReport。
- **验收**：最终总结每条结论可追溯到具体证据。

## P1 选做（把叙事补完整，约 1.5 天）

### T5 计划显式化（0.5 天）
- **做什么**：主 Agent 首轮先产出执行计划（步骤 / 角色 / 每步验收标准），人工闸门从"确认每次交接"升级为"先确认计划、再确认交接"两级；计划存入会话状态并展示在界面上。
- **为什么**：人只在开头看一次全貌比每次被动确认更接近真实工作流；面试可讲"计划/执行分离"。
- **DevFlow 出处**：Planner 产 WorkflowSpec → `requires_human_confirmation` → 执行。
- **依赖**：T1（计划本身是类型化对象）。

### T6 可观测性（0.5 天）
- **做什么**：事件总线加 `run_id`；记录每次 LLM 调用的 token / 耗时 / 模型；新增 `GET /sessions/{id}/trace` 返回决策时间线（每个决策点：输入摘要 → 模型决定 → 工具调用 → 结果）。
- **为什么**：现在 SSE 是调试级；面试题"线上 Agent 出问题怎么排查"的现成答案。
- **DevFlow 出处**：agent_events + metrics（duration/rounds/replans/success/error/skipped）+ run_id 全链路。

### T7 评测专业化（0.5 天）
- **做什么**：`eval/` 增加失败归因分类（模型波动 / 契约违反 / 轮数耗尽 / 工具失败 / 环境）；同用例集两次跑批自动对比（通过率 / 轮数 / 耗时）；用例 8 → 15+（每维度补边界用例）。
- **为什么**：8 用例只能证明"能跑"，不能证明"在改进"。
- **DevFlow 出处**：evals/suites + ragas_runner + 阈值 + 回归。

## 明确不做（及理由）

| 不做的 | 理由 |
|---|---|
| DAG 调度器 / 异步并行 | 任务图全链式依赖，无可并行分支；已专题讨论结论 |
| MCP 客户端 | 工具系统已够讲；MCP 是生态广度不是深度 |
| 知识图谱 / 代码索引 / code search | DevFlow 领域是"读仓库"，abundance 领域是"产代码" |
| git worktree 隔离 | 沙箱已是 subprocess 隔离，换形式不增加深度 |
| 调度器 / webhook / GitHub 同步 | 产品形态不同（事件驱动 vs 交互式任务） |
| ActionDraft 审批流 | 人工闸门已是同款 HITL，且更贴合流水线 |
| Ragas 全套语义指标 | 先用 T7 的归因 + 回归；语义评测作为后续谈资 |
| Memory hub / feedback 通知 | 产品功能，非核心机制 |

## 简历配套改动（与本清单联动）

现写法："为解决单 Agent 长链路任务上下文过载、缺乏质量闭环的问题……"

**问题**：上下文过载的标准解是压缩 / 检索 / 预算管理（正是 T3），不是多智能体——面试官一句"为什么不上上下文压缩"就虚；且动机落在工程细节上，没有落在角色失焦上。

**建议改为**："为解决单一 Agent 在长链路软件生产中角色混杂（需求分析 / 编码 /测试互相干扰）、质量缺乏独立验收、人工无法在关键节点介入的问题，构建多智能体协作系统……各角色独立上下文避免单提示词多目标漂移（附带收益）"

上下文隔离降级为附带收益；主动机换成"角色混杂 + 无独立验收"——正好与 T2 审查员闭环对应，动机和功能对得上。
