# abundance 改动记录

> 记录从「多智能体协作平台」到「abundance」这一轮的全部改动。
> 每条都写了**改了什么**和**为什么**，方便你面试时讲"我为什么这么设计"。

---

## 一、应用形态：从"两个黑窗口"到双击即用的单机应用

### 新增 `abundance.py`（启动器）
原来的 `start.bat` 会弹出**两个 cmd 窗口**（一个 API、一个 UI），关页面时不知道该关哪个，
窗口被误关了界面还活着、端口还占着。现在改成一个进程：

- API（uvicorn）跑在**守护线程**里，界面（Gradio）留在主线程 → 一个进程、一个窗口、一个退出动作。
- 启动后自动开浏览器，用的是 Edge/Chrome 的 `--app=` 模式 —— 没有地址栏、没有标签页，
  看起来就是个桌面应用（这就是你说的"独立页面"）。
- 端口被占用时：如果 8000 上已经有一个 abundance 后端在跑，**直接复用**而不是报错退出
  （调试时反复双击启动很常见）。
- 日志自己写 `data/logs/abundance.log`。为什么不重定向：`pythonw.exe` 没有控制台，
  出错了什么也看不见。

### 新增 `abundance.bat`（双击入口）
首次运行自动建 venv + 装依赖；`.env` 不存在时从 `.env.example` 复制一份。

### `src/agent_platform/server/ui.py`
- 窗口标题、左上角品牌名从 `AgentPlatform` 改成 `abundance`。
- `API_BASE` 改成可被环境变量覆盖，给"端口被占用换一个"留出口。
- `__main__` 里 `server_name` 从 `0.0.0.0` 改成 `127.0.0.1`（原因见第四节）。

## 二、模型切换：像 WorkBuddy 那样自己选模型、看得见价格

### 新增 `src/agent_platform/llm/models.py`（模型注册表）
纯数据表，11 个模型 × 4 家厂商：

| 厂商 | 模型 | 价格（元/百万 token，入/出） |
|---|---|---|
| 深度求索 | deepseek-chat（V4 Flash） | 1.02 / 2.04 |
| | deepseek-v4-pro | 3.18 / 6.36 |
| | deepseek-reasoner（兼容别名） | 1.02 / 2.04 |
| 阿里百炼 | qwen-plus | 0.8 / 4.8 |
| | qwen3.5-flash | 0.24 / 2.4 |
| | qwen-max | 2.4 / 9.6 |
| | qwen3-max（256K） | 2.5 / 10 |
| 智谱 | glm-4.7-flash | 免费（200K 上下文） |
| | glm-5.2 | 8 / 28 |
| 月之暗面 | kimi-k2.6 / k2.7-code（256K） | 6.5 / 27 |

每个模型都带 `strengths` / `weakness` / `best_for`，界面直接展示"擅长什么、短板是什么、适合什么活"。
每家厂商还带控制台地址和定价页链接。

> 价格是逐个核对官网定价页写进去的，**没有编**。但价格会变，用之前建议点一下界面上的"官网定价页"确认。

**注意**：DeepSeek 已经下线了 `deepseek-r1`，直接调会 400。`deepseek-chat` / `deepseek-reasoner`
现在都指向 V4 Flash。

### 新增 `src/agent_platform/llm/settings.py`
运行期设置，存在 `data/settings.json`：当前选中的模型、各家 API Key、自定义端点。

**密钥只进不出**：所有对外响应里都不含明文 key，只返回 `sk-1****cdef` 这种掩码 + "来源是界面还是环境变量"。

### 新增 `src/agent_platform/server/model_api.py`
四个端点：`GET /models`（列表+当前状态）、`POST /model`（切换）、
`POST /models/key`（存/清密钥）、`POST /models/custom`（自定义端点）、
`POST /models/test`（**打一次真实请求**）。

`/models/test` 是最实用的一步：key 错、模型名错、base_url 少个 `/v1`，
肉眼看不出区别，但一次真实调用立刻定位，还会按错误类型给提示。

### `factory.py` / `_openai_compatible.py` / `__init__.py`
- `get_llm()` 优先按注册表建 Provider；没有可用 key 时**回退到老的 `LLM_PROVIDER` 环境变量方案**，
  保证 `.env` 里只配了 `DEEPSEEK_API_KEY` 的老用法不受影响。
- 新增 `RegistryProvider`：一个通用的 OpenAI 兼容适配器，4 家厂商共用。
- **单例语义**：任务运行期间拿到的是同一个对象，所以中途换模型**不影响正在跑的那一轮**，
  只对之后新发起的调用生效。这是刻意的 —— 中途换模型会让同一条协作链的输出风格突然断裂。

### 一个我修掉的误导性问题
原来 `current_model_info()` 把两个来源混在一起报：`label` 取自"你选的模型"，
`provider` 取自"实际建出来的 Provider"。于是你选了 Qwen 但没配 key 时，界面会显示
"当前 = 通义千问 Qwen Plus"，而真实请求打到 DeepSeek 去了。

现在拆开报：多返回 `effective_model` / `effective_provider` / `is_fallback`，
顶栏那枚胶囊会直接写成 **"⚠ 通义千问 Qwen Plus 缺 API Key · 实际走 deepseek-chat"**。

## 三、界面改版：VS Code / Trae 式三栏

### 布局
```
┌──────────────┬─────────────────────────────┬──────────────┐
│ 活动栏+侧栏   │  文件树 + 代码查看器          │   聊天        │
│   264px      │        906px                │   430px      │
│              │  ┌────────┬──────────────┐  │              │
│ [历史会话]    │  │ 文件树  │   代码       │  │  模型条       │
│ [工作空间]    │  │ 232px  │              │  │  群聊         │
│              │  └────────┴──────────────┘  │  交接确认区    │
│ 会话列表      │                             │  输入区       │
└──────────────┴─────────────────────────────┴──────────────┘
```

- **最左侧**：活动栏两个按钮，点一下在「历史会话」和「工作空间」之间切换侧栏内容
  （对照 VS Code 的活动栏）。原来的"更多 → 知识库/运行统计"保留在会话视图里。
- **中间**：顶部一个根目录下拉 + 刷新 + 「只看代码」（收起文件树，给窄屏留活路），
  下面是文件树和代码查看器（带行号、按后缀高亮）。
- **右侧**：模型条 + 群聊 + 交接确认区 + 输入区。

### 踩到并修掉的两个坑
1. **右侧聊天栏被挤成 110px 的一条缝。** 原因：我用 Gradio 的 `scale=3 / scale=2` 分宽度，
   但 `.editor-col` 和 `.main-col` 两边的 CSS 都写死了 `flex: 1 1 auto !important`，
   `scale` 是靠 flex-grow 实现的，直接被盖掉了。
   改法：聊天栏给**固定宽度**（Trae / Cursor 那种右侧停靠面板），编辑器吃掉剩余空间。
   选择器必须写成 `.main-col.chat-col` 提权，因为 `.main-col` 那组规则定义在文件更靠后的位置。
2. **聊天栏里中文被逐字压成竖排**（"产品经理"排成一列）。原因：群聊区是按"整页宽度"设计的，
   头部两端对齐、成员胶囊不换行。给 `.chat-col` 作用域内加了一组换行策略就好了。

### 工作空间：改成弹系统「选择文件夹」对话框

原来只能手输绝对路径（`D:\projects\demo`）—— 既不友好也容易打错。
现在侧栏「工作空间」的主入口是一个 **📁 浏览文件夹…** 按钮，点了弹 Windows 原生
文件夹选择框，选完自动登记为工作空间（名称取文件夹名）；手输收进下面的折叠区保留。

实现上有个必须绕的坑：**本机 venv 的 Python 没有 tkinter**（精简版，
`import tkinter` 直接 ModuleNotFoundError），所以做了两条路：

1. `_pick_with_tk()` —— 有 tkinter 就用 `filedialog.askdirectory`（界面更现代）；
2. `_pick_with_shell()` —— 兜底用 Windows 自带的 COM 组件
   `Shell.Application.BrowseForFolder`，这条路不挑 Python 发行版。

两条路都**在子进程里跑**：Tk 的对话框必须在它自己的主线程里，而 Gradio 回调在工作线程，
直接调会报 "main thread is not in main loop"，或者干脆把界面卡死。

调用 Shell 那条用 `powershell -EncodedCommand`（base64 / UTF-16LE）传参：
直接拼 `-Command` 的话，标题里的中文和引号会和 PowerShell 的转义规则打架。

> 这是**单机应用**（服务只绑 127.0.0.1），所以"服务端弹窗"就等于"弹在用户自己屏幕上"。
> 哪天要对外开放，这个按钮必须去掉 —— 否则框会弹在服务器上。

### 文件树为什么用 Radio 而不是自己画 HTML 树
用 HTML 能画得和 VS Code 一模一样，但**点不动** —— Gradio 只有 Radio / Button 这类真组件的
点击事件能回到后端。所以用 Radio，标签里用全角空格造缩进层级，目录用 ▶ / ▼ 表示展开状态。

点目录会把选中值清成 `None`：否则再点同一个目录时值没变，Gradio 不触发 change，"收起"就永远点不动。

## 四、免登录

### 需求
单机自用，登录框挡住的只有自己。

### 做法
- `auth.py` 新增 `LOCAL_USER = "local"` 和 `issue_local_token()`：不校验密码直接发令牌。
- `api.py` 新增 `POST /local-token`，**限死只认回环地址**（127.0.0.1 / ::1 / localhost），
  其他来源一律 403。
- `ui.py` 里的登录页**整块删掉**（不是隐藏），`demo.load` 时自动拿本机令牌进入。

为什么要保留 token 而不是把认证链整个拆掉：会话、任务、用量都挂在 `username` 上，
拆掉会牵动一堆后端代码。真正要去掉的是**用户操作**，不是认证机制。

### 顺带补掉的两个安全洞
免登录让界面更"开放"了，所以顺手收紧了两处原来就存在的问题：

1. **`ui.py` 的 `__main__` 原来绑 `0.0.0.0`** —— 界面已经不需要登录了，这样等于
   同一局域网里任何机器都能直接打开它。改成默认 `127.0.0.1`。
2. **`/register` 原来是开放的** —— 局域网上任何人都能自己注册一个号，然后拿令牌调
   `/files/*` 读你工作空间里的源码。现在也限死本机。

## 五、新增文件浏览接口（中间栏的后端）

### 新增 `src/agent_platform/server/file_api.py`
- `GET /files/tree`：返回目录的嵌套树。两个闸门：`depth`（默认 6 层）和
  `max_nodes`（默认 1500 个节点），否则工作空间里一个大目录就能把响应撑到几十兆、浏览器直接卡死。
  自动跳过 `.git` / `.venv` / `node_modules` / `__pycache__` 等目录和 `.pyc` / `.exe` 等后缀。
- `GET /files/content`：读文本文件，上限 400KB；二进制文件不报错，回一个 `binary` 标记让界面说清楚。
- `GET /workspaces/roots`：可浏览的根目录列表。

### 安全边界（这个模块唯一真正的难点）
界面能让用户点开本地文件，所以"用户传什么路径就读什么文件"是绝对不能接受的 ——
那等于把整个磁盘暴露出去（`?path=C:\Windows\System32\config\SAM`）。

规则：**只允许读已登记工作空间目录以内的东西，其他一律 403。**
校验用 `os.path.realpath` 解析后再比前缀，这样 `..\..` 和指向外面的符号链接都会在解析后被拦下。

实测拦截结果：

| 攻击路径 | 结果 |
|---|---|
| `C:\Windows\System32\drivers\etc\hosts` | 403 |
| `<工作空间>\..\..\..\..\Windows\win.ini` | 403 |
| `C:\Users` | 403 |
| 不带令牌访问 `/files/*` | 401 |

### 一个必须注意的坑：`gr.Code` 的 `language` 是白名单
Gradio 6 的 `gr.Code`，`language` 是一份 `Literal` 白名单：
`python c cpp markdown latex json html css javascript jinja2 typescript yaml dockerfile shell r sql`。

我第一版映射表里写了 `java` / `go` / `toml` / `bat` / `powershell` —— **全部不在白名单里**，
一更新就会报错。现在表里只允许映射到白名单成员，其它语言一律落到 `markdown`
（CodeMirror 的 markdown 模式是逐字显示的，不会把代码当富文本渲染，比硬套一个错误语言安全）。
自检脚本用 27 个后缀跑过，零越界。

## 七、本轮定位并修掉的 5 个真 bug（附带 1 个是我测试脚本写错了）

上一版这里写的是"4 项断言没过、根因未定论"。现在全部查清，端到端回归 **13/13 通过**。

### Bug 1：交付目录的短后缀其实是常量 —— 同一天的同名任务互相覆盖

这是最隐蔽的一个。原实现：

```python
dir_name = f"{task_name}_{tid[:8]}"
```

而会话 id 长这样：`s_20260919_192009_283224`。**前 8 位是 `s_202609`，也就是"年月"** ——
同一天创建的每一个会话，这一段完全相同。于是"为了避免重名而加的后缀"等于没加：

```
s_20260919_184751_f9fb3e  ->  tid[:8] = "s_202609"
s_20260919_193000_a1b2c3  ->  tid[:8] = "s_202609"   ← 一模一样
```

后果：同一天跑两次同名任务，两次算到同一个目录名上，后一次的 `代码.py` **静默覆盖**前一次的。
这也解释了之前观察到的"交付目录数量对不上"。

**修法**：新增 `state.short_suffix()`，取 task_id 去掉分隔符后的**末 6 位**（会话 id 里真正随机的那段），
对 uuid 形态的 id 同样成立：

```
s_20260919_184751_f9fb3e  ->  f9fb3e
s_20260919_193000_a1b2c3  ->  a1b2c3
```

端到端实测：本次会话 `s_20260919_192009_283224` 的交付目录是
`判断回文字符串的_Python_函数_忽略大小写_283224` —— 后缀对上了。

### Bug 2：`测试状态` 永远是空串，界面一直显示"未知"

`graph.py` 的 `_build_result()` 在 `conclusion_node` **之后**执行，而这个节点最后一步是
`cleanup_state()` —— 短期状态已经被删了。于是 `load_state()` 返回空字典，
`full_state.get("测试状态", "")` 恒为空。

（同一个函数里 `功能清单` / `代码` 都有 `state.get(...)` 兜底，唯独 `测试状态` 没有兜底，
所以只有它坏了 —— 这种"同组字段里只漏一个"的写法特别容易埋雷。）

**修法**：从图状态里的 `test_passed` 推导（这个布尔值是 `conclusion_node` 在**清理之前**
读出来的，可靠）：

```python
tp = state.get("test_passed")
test_state = "通过" if tp else ("未通过" if tp is False else "")
```

### Bug 3：测试结论被关键词误判 —— 明明跑通了却记成"未通过"

`_judge_test_result()` 原来是拿 `FAIL` / `ERROR` / `Traceback` / `未通过` 这些词
去扫**整篇输出**。而测试员按要求会把 `run_python_file` 的**原始 stdout 和堆栈贴进报告** ——
里面出现 `Error`、`Traceback`、用例函数名都再正常不过。

实测就撞上了：主 Agent 复核的结论是"退出码 0、14 条用例全部通过"，
而这里判成了未通过，界面最终显示"测试状态：未通过"，**和事实相反**。

**修法**：改成"显式结论优先"。
- 提示词里要求测试员在报告最后一行固定写 `测试结论：通过` / `测试结论：未通过`；
- 判定时先用正则精确抓这一行（兼容 `**加粗**`、半角/全角冒号），抓不到才退回关键词兜底。

9 条用例全过，其中包含两条回归用例：正文里贴了含 `ERROR` / `Traceback` 的原始输出，
但只要结论行写的是"通过"，判定就必须是通过。

### Bug 4：双击启动失败 —— `.bat` 里写了中文

**这个是用户双击时当场撞上的**，我在此之前只测过 `abundance.py --no-browser`，
没测过双击 bat 这条真实路径（典型的"测了 90% 就当全测了"）。

现象：

```
'钩签?REM' 不是内部或外部命令
'thon.exe" abundance.py' 不是内部或外部命令      ← 注意前面被吃掉了一截
系统找不到指定的路径。
```

注意**报错信息本身是乱码** —— 所以从现象几乎反推不出原因。

根因：`abundance.bat` 存的是 UTF-8 并且含中文注释，而 `cmd.exe` 是用
**系统 ANSI 代码页（中文系统 = GBK）解析 bat 文件**的，
并且是在读到第 2 行 `chcp 65001` **之前**就已经按 GBK 解过前面那些行了。
UTF-8 的中文在 GBK 下解成乱码字节，其中一部分恰好是引号 / 反斜杠 / 行连接符，
把命令行**切碎** —— `".venv\Scripts\python.exe"` 前半段被吞掉，就成了 `thon.exe"`。

**修法**：`abundance.bat` 与 `start.bat` 改成**纯 ASCII**（注释也用英文），
所有中文提示交给 `abundance.py` 打印 —— Python 在 Windows 走 `WriteConsoleW`，
中文正常显示，不受当前代码页影响。

顺带做的三件事：
- 写 `_scan_bat.py` 扫全项目的 `.bat/.cmd/.vbs/.ps1` 非 ASCII 字节 ——

### Bug 5：切到「知识库 / 运行统计」后，对话区**再也回不来**（用户双击后当场撞上）

现象：界面看起来"卡住不动了，没有对话框了"。

根因在侧栏那个 Radio：

```python
nav_radio = gr.Radio(choices=[("📚 知识库", "kb"), ("📊 运行统计", "metrics")])
```

`change` 事件**只在它的值发生变化时才触发**。所以用户切到「知识库」之后，
再点同一个选项不会有任何反应 —— 而对话区的隐藏方式是 **Gradio 直接把它从 DOM 里删掉**
（实测 `chat-page display = MISSING`，不是 `display:none`），于是**没有任何办法回到对话页**，
只能刷新浏览器。

**修法**：给三条回得来的路。
1. `nav_radio` 的 choices 里加一个显式的「💬 返回对话」；
2. 知识库页和统计页**页内各放一个「← 返回对话」按钮**（用户不会想到要去点侧栏那个选项）；
3. 点「新建会话」或任意历史会话时**自动把对话区拉回来**
   （包装成 `on_new_session_focus` / `on_session_open_focus`，输出多带一个 `chat_page`）。

真机验证：点知识库 → `chat-page = MISSING`；点「← 返回对话」→ `chat-page = flex` ✓

> 顺带一提：这个 bug 和"服务进程退出"叠在一起时特别容易误判成"程序崩了"。
> 排查时我先确认了服务还活着（`/config` 能返回）、布局尺寸正常，
> 才把范围收敛到"是某个回调把它隐藏了"，最后定位到 `on_nav`。

### 顺带修掉的一个诊断陷阱：代理会把"连不上"包装成 502

用户环境里有 VPN 设的 `HTTP_PROXY=http://127.0.0.1:24589`。服务停掉之后，
`urllib` / `requests` 访问 `127.0.0.1:7860` 会**先送给代理**，代理连不上后端就回一个
**502 Bad Gateway** —— 看起来像"服务端坏了"，实际只是"服务没在跑"。

修法：`abundance.py` 启动时把回环地址塞进 `NO_PROXY`
（对 requests / urllib / httpx 都生效，且**不影响外部 API 走代理**）；
界面的内部调用再上一道保险 —— 用一个 `trust_env = False` 的专用 `requests.Session`。



### Bug 6：点历史会话**完全没反应**（用户报的第二个问题）

现象：侧栏历史会话列表能点，但点了之后聊天区纹丝不动，一直是"新会话 + 今天让他们做什么？"。

**排查过程值得完整记下来，因为这个 bug 连着骗过我两次：**

1. **第一次误判**：我写的验证脚本判定条件是"聊天区文本长度 > 100"。
   而**空状态本身就有 127 个字** —— 于是"点了没反应"被判成了"能看到内容"。
   → 教训：**判定必须比较"变化"，不能只比阈值**。
2. **第二次误判**：我以为是把它包成普通函数时（`return (*gen, ...)`）
   把生成器榨干了，改成 `yield` 转发后 —— 还是没反应。
3. **真正的根因**：函数签名是 `def on_session_select(ev: gr.SelectData, token)`。
   `gr.SelectData` **只对 `.select()` 事件有效**；换成 `.change()` 之后，
   第一个参数收到的是**组件的值本身**（一个字符串），于是 `ev.value` 当场抛
   `AttributeError` —— 而且抛在函数第一行，连我加的诊断 `print` 都没执行到，
   服务端日志里干干净净，看日志只会得出"回调压根没被调用"这个错误结论。

**修法**：签名直接收值，不再用 SelectData。

```python
def on_session_select(session_id: str, token: str):   # 不是 ev: gr.SelectData
```

绑定也要把组件自己加进 inputs：

```python
session_radio.change(on_session_open_focus, [session_radio, token_state],
                     CHAT_OUT + [chat_page])
```

**为什么从 `.select()` 换成 `.change()`**：Radio 的 `.select()` 在 Gradio 6 下不可靠
（用 CDP 发真实鼠标事件点上去也不触发）。`.change()` 稳定，代价是列表刷新导致的
`value=None` 也会触发 —— 由 `on_session_select` 开头的空值守卫挡掉（原样返回，
绝不清空聊天区）。

真机验证：点第 4 条历史会话 → 聊天区文本 **127 → 14090 字符**，
头部变成 `判断回文字符串的_Python_函数_忽略大小写 · 已完成` ✓

> 附带经验：`element.click()` 是 JS 合成事件，某些组件不认；
> 用 CDP 的 `Input.dispatchMouseEvent` 发真实指针事件更接近用户操作。
> 这个 bug 里**两种点击都试过**，都没进回调 —— 才把方向从"前端点击"
> 扭到"后端函数签名"。方向扭对了，一行就修好。

### 不是 bug：重复提交返回 200

上一版怀疑这里有问题。查清了 —— **是我的测试脚本期望写错了**。

原来的场景 C 拿"已经 stopped"的会话来测重复提交。可那个会话的执行线程早就结束了，
此时允许再次提交是**正确行为**（用户终止后想接着改需求很常见）。
409 的语义是"这个会话现在正忙"。

改成在一个真在跑的会话上验证：先启动 → 紧接着二次提交 → **实测 409** ✓。

### 另外两个之前列出的症状，已确认消失

- **"一次任务产生 10 个空交付目录、目录名退化成 `任务_<时间戳>`"**：
  这是"短期记忆降级路径读写不一致"的下游症状（`load_context` 读旧路径、`save_context` 写新路径），
  在上一轮修 `short_term.py` 时已经解决。本轮端到端实测：目录名带任务名、且本次任务只新建了 1 个目录。
- **"交接卡片上'上游完成的工作'是空的"**：同样随状态链路修复而消失，
  实测交接卡片上能看到完整的上游产出摘要。

### 还剩一个已知不足（不是 bug，是模型行为）

测试员偶尔会用英文写报告（提示词里已经要求中文，但模型不一定听），
而且会把工具原始输出直接贴进正文。这一轮已经把提示词写得更硬（要求中文 + 固定结论行 + 原始输出放代码块），

其实主 Agent 已经这么干了（实测它自己发现"测试报告不合格"并退回了一次）。

## 十一、专业化升级七连（参照 DevFlow-AI 机制层，全部落地）

> 2026-10-18。参照对象是 DevFlow-AI（注意：后来查明它也是小林coding 付费课程项目，
> 只作机制参照，不进简历）。七项全部实现并提交，测试 64/64 通过。
> 另外：课程第 7 章的 quality_gate / evidence_contract（MewHelp 线资料）也吸收进了 T1/T4 的设计。

### 1. 结构化输出契约（`agents/contract.py`，commit a724cb6 后续）
- 三个子 Agent 输出改为"信封式 JSON"：`{role, status, artifacts, evidence[], confidence}`。
- `sub_agents.py` 解析校验：必填字段缺失 → 记 `failed` 重试一次；交付物落盘只接受
  `status=ok` 且 artifacts 非空。**治的是 10-13 那次空壳输出覆盖 19KB 真代码的坑**——
  平台现在能区分"做完了"和"说了句漂亮话"。
- 配 `tests/test_contract.py`（含"贴原始输出不误判"的回归用例）。

### 2. 独立审查员 + 置信度阈值（`agents/reviewer.py`）
- 新增"审查员"角色：只喂交付物+证据，**不给对话历史**（切断"自审自评"）。
- LangGraph 图里 agent → **review** → conclusion；`verdict=reject` 走打回通道重做；
  `confidence<0.6` 或无证据 → 自动重做。
- 主 Agent 被迫亲自干测试员的活（计算器任务 19 轮）的问题从此有制度性解法。

### 3. 上下文预算管理（`agents/context.py`）
- 每次调 LLM 前按预算分级拼装，超预算压缩早期轮次，**工具结果（证据）不压缩**。
- `max_turns` 硬截断升级为"轮数 + 预算"双闸——长任务不再中途失忆。

### 4. 证据链与引用
- RAG 注入的记忆带来源前缀 `[记忆#id · 类型 · 日期]`；
- conclusion 产出"结论 + 证据指针"，`任务规划/证据清单` 进最终 result；
- 交付卡片展示证据链与审查次数，测试员提示词强化"结论行必须贴运行证据"。

### 5. 计划显式化 + 两级人工闸门（`tools/builtins/dispatch.py`）
- 主 Agent 首轮输出即执行计划，落图状态 + 存储状态双写；规划期的纯文本输出
  视为计划修订（计划被打回后重写的版本也能进闸门）。
- 闸门升两级：**开场先确认"执行计划"（看一次全貌），通过后第一次 dispatch 免确认；
  之后的每次交接照旧走交接闸门（看上游实际产出）**。
- 为什么第一级放 dispatch 入口：那里是全项目唯一交接点，天然覆盖所有开场路径。

### 6. 可观测性：token 计量 + 决策时间线（`runtime/usage.py` + trace 接口）
- `OpenAICompatibleProvider` 三条调用路径（chat / chat_collect / structured）全部
  记录 token 用量与耗时，按 tag 分类；流式走 `stream_options.include_usage`。
- 新增 `GET /sessions/{id}/trace`：返回决策时间线（每个决策点的输入摘要 → 模型
  决定 → 工具调用 → 结果）。面试题"线上 Agent 出问题怎么排查"的现成答案。

### 7. 评测专业化：失败归因 + 自动回归对比（`eval/attribution.py`）
- 每条用例自动归因：通过 / 模型输出波动（测试未通过）/ 轮数耗尽 / 工具失败 /
  运行时错误 / 未完成——8 用例只能证明"能跑"，归因才能证明"在改进"。
- 同用例集两次跑批自动对比：通过率降=回退、轮数/耗时降=改进（方向不同判定不同）。
- `eval_tasks.py` 输出改到项目内 `eval/output/`（带时间戳），不再写外部临时目录。
